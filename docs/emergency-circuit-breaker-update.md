# AX 负载保护 - 紧急熔断机制更新

## 更新背景

根据实测反馈，IDA Pro 等应用会直接导致程序崩溃。原有的"事后暂停"机制无法防止崩溃，因为采样过程本身就会卡死主线程。

## 新增：运行时紧急熔断

### 核心改进

在 AX 树遍历**过程中**实时检测开销，一旦触发紧急阈值立即中断：

```swift
while index < queue.count, visited < nodeBudget {
    visited += 1
    
    // 每处理 10 个节点检查一次
    if visited % 10 == 0, meter.shouldAbort() {
        break  // 立即中断
    }
    
    // ... 继续处理
}
```

### 紧急阈值（硬编码）

- **50 次 IPC 调用**（远低于普通过载的 700 次）
- **0.1 秒主线程时间**（远低于普通过载的 0.6 秒）

### 触发后果

- **单次触发即永久暂停**（`recheckAt = .distantFuture`）
- **不再自动试探**（避免反复崩溃）
- **只能手动恢复**（用户明确操作）
- **再次触发立即再次永久暂停**

### 与普通过载的区别

| 特性 | 紧急熔断 | 普通过载 |
|------|---------|----------|
| 触发阈值 | 50 IPC / 0.1s | 700 IPC / 0.6s |
| 检测时机 | 遍历中实时 | 采样后评估 |
| 触发条件 | 单次 | 连续 3 次 |
| 暂停时长 | 永久 | 10 分钟 |
| 恢复方式 | 仅手动 | 自动试探 + 手动 |

## UI 更新

设置界面显示紧急中止状态：
```
□ IDA Pro           已触发紧急熔断（永久暂停）  [恢复]
```

## 实测效果

- **IDA Pro**：触发紧急熔断，程序不再崩溃
- **复杂 Web 页面**：触发普通过载，10 分钟后自动恢复
- **正常页面**：不触发任何保护，正常运行

## 代码变更

- `AXReadMeter`：增加 `shouldAbort()` 方法和紧急阈值
- `AXLoadSample`：增加 `emergencyAborted` 字段
- `AXLoadGovernor.Suspension`：增加 `emergencyAborted` 字段，区分两种暂停
- `ContextDetector.collectText`：每 10 个节点检查一次 `meter.shouldAbort()`
- `SettingsView`：显示紧急中止标记

## 测试结果

✅ 所有 93 个单元测试通过

## 建议

对于 IDA Pro 等已知会触发紧急熔断的应用：
1. 首次触发后保持永久暂停状态
2. 使用窗口记忆模式（仍然有效）
3. 配置关键词规则（不受智能模式影响）
4. 不建议手动恢复（会再次触发）
